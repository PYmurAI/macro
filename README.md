# デタリキZ 共同戦線イベント自動化ツールの開発

## 目的

ブラウザゲーム「デタリキZ」の共同戦線イベントにおける繰り返し操作を、Playwrightを使用して自動化する。

最終的には、共同戦線イベントを指定した条件まで自動周回できるツールを目指す。

## 技術構成

- Node.js
- Playwright
- JavaScript
- 実行環境：Mac / Windows
- 操作対象：PCブラウザ版デタリキZ

## 基本方針

- Playwrightでブラウザを起動・操作する。
- ログインは手動で行い、認証情報をコードに埋め込まない。
- ブラウザのログイン状態を可能な範囲で保持する。
- ゲーム画面がCanvas/WebGLの場合は座標クリックを利用する。
- 必要に応じてスクリーンショットによる画面状態判定を導入する。
- 固定時間の待機だけに依存せず、画面遷移を確認して操作する。
- ゲーム内部APIの直接呼び出しや通信内容の改変は行わない。
- ゲームの利用規約を確認し、自動操作が禁止されている場合は実行しない。

## フェーズ1：調査・操作確認

1. Playwrightでブラウザを起動する。
2. ユーザーが手動でログインする。
3. 共同戦線イベント画面まで手動で移動する。
4. ゲーム画面のDOM構造を調査する。
5. Canvas/WebGLで描画されているか確認する。
6. 共同戦線1周分の操作手順を確認する。
7. 各操作に必要なクリック位置と画面遷移を記録する。

この段階では自動周回を実装せず、操作方法と技術的な制約を確認する。

## フェーズ2：1周分の自動化

以下の操作を自動化する。

1. 共同戦線の出撃画面を確認する。
2. 出撃ボタンをクリックする。
3. 戦闘開始を確認する。
4. 戦闘終了まで待機する。
5. リザルト画面を確認する。
6. リザルト画面を閉じる。
7. 次の出撃が可能な状態まで戻る。

画面が想定外の状態になった場合は操作を停止する。

## フェーズ3：連続周回

フェーズ2が安定して動作した後に実装する。

- 指定回数の自動周回
- 周回回数のカウント
- スタミナ不足などによる自動停止
- エラー発生時の自動停止
- 手動停止機能
- 実行ログの記録

## 安定性・安全性

- 画面遷移にはタイムアウトを設定する。
- 想定外の画面ではクリックを続行しない。
- 画面判定に失敗した場合はスクリーンショットを保存する。
- 誤クリックを防ぐため、ウィンドウサイズを固定する。
- 座標クリックは画面サイズに応じた相対座標で管理することを検討する。
- 課金、アイテム購入、通貨消費などの操作は自動化しない。
- CAPTCHAなどの認証・不正操作対策を回避しない。

## 開発の進め方

最初から全機能を実装せず、段階的に進める。

**まずはフェーズ1のみ実施すること。**

実際のゲーム画面を調査し、DOM操作で対応できるか、Canvas/WebGLへの座標クリックが必要かを確認する。

調査結果と推奨する実装方法を報告し、ユーザーの確認を得てからフェーズ2へ進む。

不明な操作手順やゲーム仕様については推測で実装せず、ユーザーに確認すること。
